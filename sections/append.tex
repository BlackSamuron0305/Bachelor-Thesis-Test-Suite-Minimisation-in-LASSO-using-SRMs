\subsubsection{C2 Justification}

Coverage preservation measures the percentage of structural requirements (lines, branches, methods) retained in the minimised suite. Complete coverage (100\% = score 5/5) is essential for LASSO to maintain structural adequacy.

\textbf{5/5 Guarantees (8 algorithms):} Greedy heuristics guarantee coverage by algorithm design: each iteration selects a test covering additional uncovered requirements until all are satisfied. Exact methods (ILP, NEMO, ITSM) enforce coverage constraints as hard constraints in their formulation~\cite{lin2018,yoo2012}.

\textbf{4/5 High but Configurable (1 algorithm):} Many-Objective EA formulates coverage as an explicit objective, permitting decision-makers to prioritise coverage versus other criteria (e.g., suite size, mutation score)~\cite{wei2017}. Coverage is high but not guaranteed.

\textbf{1--2/5 Variable (4 algorithms):} Search-based metaheuristics (GA, PSO/ABC) evolve solutions via Pareto fronts or fitness landscapes, resulting in multiple feasible solutions with variable coverage depending on parameter configuration and convergence~\cite{yoo2012}. Data-driven methods (Similarity-Based, Overlap-Aware) depend on clustering thresholds or time budgets, which affect retention rates~\cite{bach2017,khan2020}.

\subsubsection{C4 Justification: The Critical Coverage-Mutation Gap}

Mutation score preservation is the most critical evaluation criterion and reveals a documented gap in test-suite minimisation research.

\textbf{The Gap:} Jehan et al.~\cite{jehan2023} demonstrate that coverage-only minimisation loses 0--21\% mutation capability depending on reduction aggressiveness. With adequate reduction (100\% coverage retained), loss is 0--5\%. This proves structural redundancy does not imply semantic redundancy~\cite{jehan2023}.

\textbf{5/5 Solutions (3 algorithms):} 
\begin{itemize}
  \item \textbf{Delayed Greedy:} Achieves 0\% mutation loss for adequate reduction, maintaining equivalent fault-detection~\cite{jehan2023}.
  \item \textbf{Many-Objective EA+Mutation:} Wei et al.~\cite{wei2017} demonstrate that explicitly optimising mutation score in multi-objective formulations (NSGA-II, MOEA/D, IBEA, SPEA2-SDE) achieves 95--100\% mutation retention while reducing test cost. This validates mutation-aware approaches.
  \item \textbf{MA-EHGS:} Integrates mutation testing into greedy selection via $\beta$-parameter weighting. This directly implements the validated approach demonstrated by Wei et al., achieving expected minimal loss through explicit mutation consideration.
\end{itemize}

\textbf{3/5 Coverage-Only Greedy (2 algorithms):} Classical Greedy and HGS achieve 0--5\% mutation loss for adequate reduction but lack mutation-aware design. No explicit mechanism to preserve mutation capability.

\textbf{0/5 No Evaluation (8 algorithms):} Most algorithms in the literature lack mutation evaluation. Enhanced HGS (the baseline for MA-EHGS), exact methods (ILP, NEMO), interaction-based methods (ITSM), and most metaheuristics lack empirical mutation studies~\cite{gladston2015,yoo2012,lin2018,nishino2020}. This gap motivates mutation-aware approaches.

\section{MA-EHGS Selection Justification}\label{app:selection}

MA-EHGS achieves the highest score (23/25), outperforming Classical Greedy (22/25), and is selected for LASSO integration based on the following strategic advantages:

\subsection{Mutation-Awareness Advantage (C4: Key Differentiator)}

\begin{itemize}
  \item \textbf{Classical Greedy:} C4 score = 3/5 (0--5\% mutation loss for adequate reduction, no explicit mutation mechanism).
  \item \textbf{MA-EHGS:} C4 score = 5/5 (designed for minimal loss via explicit mutation weighting).
  \item \textbf{Advantage:} +2 points in critical criterion (mutation preservation).
\end{itemize}

\textbf{Evidence:} Jehan et al.~\cite{jehan2023} demonstrate that coverage-only minimisation loses 0--21\% mutation capability. Wei et al.~\cite{wei2017} show that integrating mutation as an explicit objective in many-objective evolutionary algorithms achieves 95--100\% retention. MA-EHGS directly implements this validated concept through $\beta$-parameter weighting, addressing the documented gap.

\subsection{Multi-Criteria Optimality}

MA-EHGS excels across all dimensions:
\begin{itemize}
  \item \textbf{C1 (SRM):} \checkmark (mandatory pass)
  \item \textbf{C2 (Coverage):} 5/5 (100\% guaranteed)
  \item \textbf{C3 (Reduction):} 4/5 (strong 70--75\%)
  \item \textbf{C4 (Mutation):} 5/5 (explicit preservation)
  \item \textbf{C5 (Scalability):} 5/5 (O(nm) polynomial)
  \item \textbf{C6 (Feasibility):} 4/5 (straightforward, one parameter)
\end{itemize}

\textbf{Comparison to nearest competitor:} Classical Greedy (22/25) lacks mutation-awareness (C4: 3/5 vs. 5/5) and provides no mechanism to address the documented coverage-mutation gap.

\subsection{Alternatives and Trade-offs}

\begin{description}
  \item[Delayed Greedy (17/25)] Achieves superior mutation preservation (5/5) but suffers from prohibitive $O(n^2m)$ complexity (C5: 2/5). For LASSO's large-scale requirements (1,000+ tests), quadratic complexity is unsuitable. Delayed greedy would require seconds to hours for large SRMs, while MA-EHGS completes in seconds~\cite{tallam2005}.
  
  \item[Many-Objective EA+Mutation (17/25)] Provides excellent mutation preservation (5/5) but suffers from poor scalability (C5: 2/5) and extensive parameter tuning (C6: 2/5). Wei et al.~\cite{wei2017} demonstrate mutation-aware capability but at significantly higher computational cost than greedy approaches. Generation-based metaheuristics with $O(gnm)$ complexity are prohibitive for interactive minimisation~\cite{yoo2012}.
  
  \item[Enhanced HGS (18/25)] Achieves strong coverage and scalability but lacks any mutation evaluation (C4: 0/5). Enhanced HGS is the empirically validated baseline; MA-EHGS extends it with explicit mutation weighting while preserving all coverage and scalability advantages~\cite{gladston2015}.
  
  \item[Classical Greedy (22/25)] Near-tie score but lacks mutation-awareness. Does not address the documented coverage-mutation gap identified by Jehan et al.~\cite{jehan2023}.
\end{description}

\subsection{Practical Advantages for LASSO}

\begin{itemize}
  \item \textbf{SRM Alignment:} MA-EHGS requirements-matrix formulation aligns perfectly with LASSO's SRM representation, where structural coverage (JaCoCo metrics) and mutation kills serve as requirements.
  
  \item \textbf{Computational Efficiency:} $O(nm)$ complexity enables processing large SRMs (1,000+ tests, 500+ requirements) in seconds, outperforming Delayed Greedy ($O(n^2m)$) and metaheuristics ($O(gnm)$) by orders of magnitude.
  
  \item \textbf{Parameterised Tuning:} Single $\beta$-parameter permits empirical optimisation via grid search ($\beta \in \{0.5, 0.6, 0.7, 0.8, 0.9\}$). $\beta=0$ reproduces validated Enhanced HGS baseline; $\beta=0.7$ balances coverage and mutation emphasis; higher $\beta$ prioritises mutation preservation.
  
  \item \textbf{Empirical Grounding:} Unlike metaheuristic approaches requiring extensive tuning and lacking reproducibility, MA-EHGS extends a published, empirically validated algorithm~\cite{gladston2015} with a principled extension justified by recent literature~\cite{wei2017}.
  
  \item \textbf{Language-Independent:} Operates on SRM matrices without CFG dependencies, enabling consistent minimisation across diverse programming languages and system architectures~\cite{bach2017}.
\end{itemize}

\chapter{Mutation-Aware Enhanced HGS Pseudocode}
\label{app:pseudocode}

This appendix provides precise pseudocode for the Mutation-Aware Enhanced HGS algorithm used in this thesis. The notation follows the requirements-matrix literature~\cite{gladston2015} and adopts bitset-based operations for efficiency.

\subsection*{Notation}
\begin{itemize}
	\item Input: SRM $M$ from LASSO (stimuli $\times$ systems, structured response objects); target system index $j$
	\item Preprocessing: Extract coverage data and mutation information from response objects $M_{ij}$ to construct requirements matrix (tests $T = \{t_1,\dots,t_n\}$ as stimuli; structural requirements $R_{\text{struct}} = \{r_1,\dots,r_m\}$ as coverage elements; mutants $R_{\text{mut}} = \{m_1,\dots,m_p\}$ as additional requirements; unified requirements $R = R_{\text{struct}} \cup R_{\text{mut}}$)
	\item For each test $t_i$, let $R_i \subseteq R$ denote the set of requirements covered by $t_i$ (including mutants killed)
	\item Parameters: Coverage weight $\alpha \in [0,1]$ (default $0.3$), mutation weight $\beta \ge 0$ (default $0.7$); when $\beta = 0$, reproduces pure coverage-based minimisation and when $\alpha = 0$, reproduces pure mutation-based minimisation
	\item Output: Reduced SRM $M'$ containing selected stimuli (rows) with original schema preserved
\end{itemize}

\subsection*{Algorithm}
\begin{framed}
\noindent\textbf{Procedure} MAEHGS($M$, $\alpha$, $\beta$)\\
\textbf{Input:} Requirements matrix $M \in \{0,1\}^{n \times m}$ where $M_{ij} = 1$ indicates test $t_i$ satisfies requirement $r_j$ (unified structural and mutation requirements); coverage weight $\alpha \in [0,1]$ (default $0.3$), mutation weight $\beta \ge 0$ (default $0.7$)\\
\textbf{Output:} Minimal (heuristic) subset $S \subseteq T$ preserving all requirements\\[4pt]

\noindent\textbf{Phase 1: Essential Test Selection}\\
1. Compute requirement cardinalities: $|T_j| = |\{ t_i \mid M_{ij} = 1 \}|$ for all $r_j \in R$\\
2. Initialize $S \leftarrow \emptyset$, $R_{\text{uncov}} \leftarrow R$ (set of uncovered requirements)\\
3. For each requirement $r_j$ with $|T_j| = 1$:\\
\quad Let $t_i$ be the unique test covering $r_j$ (i.e., $M_{ij} = 1$)\\
\quad Add $t_i$ to $S$ (if not already added)\\
\quad Remove all requirements covered by $t_i$ from $R_{\text{uncov}}$: $R_{\text{uncov}} \leftarrow R_{\text{uncov}} \setminus R_i$

\noindent\textbf{Phase 2: Weighted Greedy Selection}\\
4. While $R_{\text{uncov}} \neq \emptyset$:\\
\quad 4.1 For each remaining test $t_i$ not in $S$:\\
\quad\quad Let $\text{newCov}_{\text{struct}} = R_i \cap R_{\text{uncov}} \cap R_{\text{struct}}$ (uncovered structural requirements)\\
\quad\quad Let $\text{newCov}_{\text{mut}} = R_i \cap R_{\text{uncov}} \cap R_{\text{mut}}$ (uncovered mutant kills)\\
\quad\quad Score($t_i$) $= \alpha \cdot |\text{newCov}_{\text{struct}}| + \beta \cdot |\text{newCov}_{\text{mut}}|$\\
\quad 4.2 Select $t_{i^*} = \arg\max_{t_i} \text{Score}(t_i)$\\
\quad\quad (ties broken by total new coverage $|\text{newCov}_{\text{struct}}| + |\text{newCov}_{\text{mut}}|$)\\
\quad 4.3 Add $t_{i^*}$ to $S$\\
\quad 4.4 Update $R_{\text{uncov}} \leftarrow R_{\text{uncov}} \setminus R_{i^*}$ (remove newly covered requirements)\\
5. Return $S$
\end{framed}

\subsection*{Complexity}
Phase 1 computes cardinalities in $O(nm)$ and selects essential tests in $O(nm)$. Phase 2's greedy loop executes at most $n$ iterations, each scanning remaining tests and computing scores in $O(m)$ time. Overall complexity is $\mathbf{O(nm)}$ for both time and space, matching classical greedy and Enhanced HGS~\cite{gladston2015}, while improving upon the original HGS's $O(nm \log m)$ overhead~\cite{harrold1993,yoo2012}. The dual-parameter weighting ($\alpha$, $\beta$) adds no asymptotic overhead.

\section{SRM Coverage Extraction Specification}
\label{app:srm}

We specify the process for extracting per-test granular coverage information from LASSO Stimulus--Response Matrices (SRMs) for use by the minimisation algorithm:

\subsection{SRM Structure and Storage}
LASSO SRMs are stored in Apache Ignite distributed cache with the following schema:
\begin{itemize}
	\item Rows (stimuli) represent test sequences, method invocations, or API calls
	\item Columns (systems) represent executable software units under test
	\item Cells contain structured response objects $M_{ij}$ with execution results from system $j$ responding to stimulus $i$
	\item Cache keys (\texttt{CellId}): contain \texttt{executionId}, \texttt{systemId}, \texttt{adapterId}, \texttt{variantId} (original/mutant), \texttt{sheetId} (test name or coverage key), cell coordinates (x, y)
	\item Cache values (\texttt{CellValue}): contain execution outcomes, coverage elements, or metric values
\end{itemize}

\subsection{Per-Test Coverage Collection}
The implementation uses JaCoCo instrumentation with per-test isolation via lifecycle hooks:

\begin{enumerate}
	\item \textbf{Test Lifecycle Integration:} For each test $t_i$:
	\begin{itemize}
		\item Before execution: \texttt{jaCoCoContainer.start()} initialises or resets coverage counters
		\item During execution: JaCoCo instruments class bytecode and collects coverage
		\item After execution: \texttt{jaCoCoContainer.stop()} retrieves \texttt{CoverageBuilder} with isolated per-test data
	\end{itemize}
	
	\item \textbf{Granular Coverage Storage:} Coverage data stored with language-agnostic prefix \texttt{COVERAGE\_testName}:
	\begin{itemize}
		\item Each covered line: \texttt{sheetId = "COVERAGE\_testName", type = "LINE", value = lineNumber}
		\item Each covered branch: \texttt{sheetId = "COVERAGE\_testName", type = "BRANCH", value = lineNumber}
		\item Each covered method: \texttt{sheetId = "COVERAGE\_testName", type = "METHOD", value = signature}
	\end{itemize}
	Storage format enables uniform treatment across languages (JaCoCo for Java, coverage.py for Python, Istanbul for JavaScript in future extensions).
	
	\item \textbf{Mutation Result Collection:} Test outcomes on original and mutant variants stored as:
	\begin{itemize}
		\item \texttt{sheetId = "testName()", variantId = "original", type = "value", value = outputValue}
		\item \texttt{sheetId = "testName()", variantId = "mutantN", type = "value", value = outputValue}
		\item Cell-by-cell comparison: mutant killed if \textit{any} cell output differs between original and mutant
	\end{itemize}
\end{enumerate}

\subsection{Data Collector Query Strategy}
\texttt{SRMDataCollector} retrieves data from Ignite cache via SQL queries:

\begin{enumerate}
	\item \textbf{Coverage Query:} \texttt{SELECT * WHERE executionId = ? AND variantId = 'original' AND sheetId LIKE 'COVERAGE\_\%'}
	\begin{itemize}
		\item Returns all per-test coverage entries for target execution
		\item Test name extracted by removing \texttt{COVERAGE\_} prefix
		\item Test names normalised (remove adapter suffixes like \texttt{\_0}, \texttt{\_1})
	\end{itemize}
	
	\item \textbf{Mutation Query:} \texttt{SELECT * WHERE executionId = ? AND systemId = ? AND type = 'value'}
	\begin{itemize}
		\item Returns test outcomes across all variants (original + mutants)
		\item Organises by test name → cell position → variant
		\item Mutant marked killed if outputs differ at any coordinate
	\end{itemize}
	
	\item \textbf{Requirements Matrix Construction:}
	\begin{itemize}
		\item Tests $T = \{t_1, \ldots, t_n\}$ extracted from distinct \texttt{sheetId} values
		\item Coverage requirements: \texttt{"LINE:42"}, \texttt{"BRANCH:15"}, \texttt{"METHOD:push(I)V"}
		\item Mutation requirements: \texttt{"MUTANT:systemId\_mutantN"}
		\item Unified set $R = R_{\text{struct}} \cup R_{\text{mut}}$
	\end{itemize}
\end{enumerate}

\subsection{Critical Implementation Details}
\begin{itemize}
	\item \textbf{Test-System Mapping:} Coverage preserved per test–system pair; duplication across all systems was a critical bug that caused algorithm to select only 1 test (fixed by using actual \texttt{systemId} from \texttt{CellId})
	\item \textbf{Null-Safe Comparison:} Mutation detection handles null outputs correctly (both null = same; one null = different)
	\item \textbf{Test Name Normalisation:} Coverage names (\texttt{testName\_0}) and mutation names (\texttt{testName()}) unified by regex removal of suffixes
\end{itemize}

\subsection{Output Format}
The minimiser produces a reduced SRM $M'$ where:
\begin{itemize}
	\item Rows correspond to selected stimuli (subset of original)
	\item Columns preserve original system structure
	\item Cells retain original structured response objects
	\item Schema remains identical to input SRM for seamless integration with LASSO analyses
\end{itemize}

This extraction process ensures language independence by operating purely on SRM-level abstractions without requiring source code access or language-specific program structure.
