\chapter{Detailed Evaluation Tables for Comparative Analysis}\label{app:evaluation-tables}

This appendix provides the detailed evaluation tables and justifications for the algorithm scores discussed in Chapter~\ref{chap:comparison}. The tables are aligned with the technique families and criteria introduced in Chapters~\ref{chap:literature-review} and~\ref{chap:comparison} and focus on approaches that can be expressed on a Stimulus--Response Matrix (SRM).

The following algorithms and families are considered:

\begin{itemize}
  \item Classical Greedy (CG)
  \item Harrold--Gupta--Soffa (HGS)
  \item Delayed Greedy (DG)
  \item Enhanced HGS (EHGS)
  \item Mutation-Aware Enhanced HGS (MA-EHGS; this thesis)
  \item Exact ILP/SAT set-cover formulations (ILP)
  \item NEMO (nonlinear integer programming)~\cite{lin2018}
  \item Mutation-aware many-objective evolutionary algorithms (MOEA-mu; Wei et al.~\cite{wei2017})
  \item Coverage-based search-based techniques (GA/PSO/ABC)
  \item Similarity- and overlap-based methods (SIM/OV; e.g.\ Bach et al.~\cite{bach2017}, Khan et al.~\cite{khan2020})
  \item REDUNET (set-cover + CFG-based optimisation)~\cite{mongiovi2020}
\end{itemize}

Scores for C2--C6 use a scale from 0 (poor) to 5 (very strong). C1 is a mandatory SRM-compatibility check (pass/fail).

Greedy and exact matrix-based algorithms allow LASSO to guarantee structural adequacy (100\% of the chosen coverage metric) in SRM form. MA-EHGS preserves this guarantee for all requirements included in the matrix while extending the requirement set to include mutants.

\subsubsection*{C4 Discussion: The Coverage--Mutation Gap}

The literature documents a clear gap between structural coverage and mutation score:

\begin{itemize}
  \item Noemmer \& Haas show that coverage-based minimisation can lead to relative mutation score losses between 3.5\% and 21\% depending on subject and reduction level, even when structural adequacy is preserved~\cite{noemmer2020}. 
  \item Jehan \& Wotawa demonstrate that, when all mutants are treated as requirements, several greedy algorithms reduce suites by around 70\% \emph{without} compromising mutation-based fault detection~\cite{jehan2023}.
  \item Wei et al.\ show that explicitly including mutation score as an objective allows many-objective EAs to reduce cost while maintaining defect detection ability~\cite{wei2017}.
\end{itemize}

MA-EHGS is designed to incorporate mutation information in a deterministic, SRM-based greedy algorithm and can be configured to preserve mutants of interest while still achieving meaningful reduction.

\section{MA-EHGS Selection Justification}\label{app:selection}

The multi-criteria analysis shows that several algorithms perform well:

\begin{itemize}
  \item \textbf{Greedy heuristics} (CG, HGS, DG, EHGS) offer excellent coverage preservation (C2), strong reductions (C3), good scalability (C5), and high implementation feasibility (C6)~\cite{harrold1993,gladston2015,yoo2012,noemmer2020,jehan2023}.
  \item \textbf{Exact methods} (ILP, NEMO) are optimal for their formulations (C3) but limited by scalability and integration complexity (C5--C6)~\cite{elbaum2002,yoo2012,lin2018}.
  \item \textbf{MOEA-mu} excels in mutation-awareness (C4) while offering good reduction (C3), but at higher computational and implementation cost~\cite{wei2017}.
  \item \textbf{Similarity-/overlap-based methods} (SIM/OV) scale well (C5) and integrate reasonably (C6), but target prioritisation under time budgets rather than strict minimisation~\cite{bach2017,khan2020}.
\end{itemize}

Classical Greedy and MA-EHGS both reach a total of 22/25. The decisive difference lies in C4 (mutation score preservation):

\begin{itemize}
  \item \textbf{Classical Greedy:} Mutation is not modelled explicitly. Empirical work shows that coverage-only minimisation can lead to noticeable mutation score losses when coverage thresholds or requirements are relaxed~\cite{noemmer2020}. When all mutants are treated as requirements, greedy algorithms can avoid mutation losses~\cite{jehan2023}, but this is a property of the configuration rather than of the algorithm design.
  \item \textbf{MA-EHGS:} Treats mutants as explicit requirements and supports weighting them via $\beta$. In LASSO’s configuration, MA-EHGS is used to incorporate mutation information directly into selection decisions and can be configured to retain the mutants of interest while still yielding strong reduction, as demonstrated on the case studies (Section~\ref{app:benchmarks}).
\end{itemize}

For LASSO’s SRM setting, this thesis therefore selects \textbf{MA-EHGS} as the primary minimisation algorithm, justified by:

\begin{itemize}
  \item SRM-only operation (C1),
  \item full structural coverage preservation for the chosen coverage metric (C2),
  \item strong reduction effectiveness comparable to other greedy heuristics (C3),
  \item explicit support for mutation information and very high mutation retention (C4),
  \item polynomial scalability suitable for large SRMs (C5),
  \item and straightforward integration with LASSO’s existing architecture (C6).
\end{itemize}

Classical Greedy remains a natural baseline and backup option, especially when mutation information is unavailable.

\chapter{Mutation-Aware Enhanced HGS Pseudocode}
\label{app:pseudocode}

This appendix provides precise pseudocode for the Mutation-Aware Enhanced HGS (MA-EHGS) algorithm. The notation follows requirements-matrix formulations as used for EHGS~\cite{gladston2015} and other set-cover-based techniques.

\subsection*{Notation}

\begin{itemize}
  \item $T = \{t_1,\dots,t_n\}$: set of tests (rows).
  \item $R_{\text{struct}} = \{r_1,\dots,r_m\}$: structural requirements (e.g.\ lines, branches, methods).
  \item $R_{\text{mut}} = \{m_1,\dots,m_p\}$: mutation requirements (mutants killed by the original suite).
  \item $R = R_{\text{struct}} \cup R_{\text{mut}}$: unified requirement set (columns).
  \item $M \in \{0,1\}^{n \times |R|}$: binary requirements matrix; $M_{ij} = 1$ iff test $t_i$ satisfies requirement $r_j$.
  \item $R_i = \{r_j \in R \mid M_{ij}=1\}$: set of requirements covered by test $t_i$.
  \item Weights: $\alpha \in [0,1]$ for structural requirements, $\beta \ge 0$ for mutants (typical: $\alpha = 0.3$, $\beta = 0.7$). Setting $\beta = 0$ recovers a purely coverage-based EHGS. Setting $\alpha = 0$ would prioritise mutants only.
\end{itemize}

\subsection*{Algorithm}

\begin{framed}
\noindent\textbf{Procedure} MAEHGS($M$, $\alpha$, $\beta$)\\
\textbf{Input:} Requirements matrix $M \in \{0,1\}^{n \times |R|}$, weights $\alpha \in [0,1]$, $\beta \ge 0$\\
\textbf{Output:} Selected test subset $S \subseteq T$\\[4pt]

\noindent\textbf{Phase 1: Essential Test Selection}\\
1. For each requirement $r_j \in R$, compute its set of covering tests:
\[
  T_j = \{ t_i \in T \mid M_{ij} = 1 \}, \quad |T_j| = \text{cardinality of }T_j
\]
2. Initialise selected tests and uncovered requirements:
\[
  S \leftarrow \emptyset,\quad R_{\text{uncov}} \leftarrow R
\]
3. For each requirement $r_j \in R$ with $|T_j| = 1$:
\begin{itemize}
  \item Let $t_i$ be the unique test in $T_j$.
  \item Add $t_i$ to $S$ (if not already selected).
  \item Remove all requirements covered by $t_i$:
  \[
    R_{\text{uncov}} \leftarrow R_{\text{uncov}} \setminus R_i
  \]
\end{itemize}

\noindent\textbf{Phase 2: Weighted Greedy Selection}\\
4. While $R_{\text{uncov}} \neq \emptyset$:
\begin{itemize}
  \item For each test $t_i \in T \setminus S$:
  \begin{itemize}
    \item $\text{newCov}_{\text{struct}}(t_i) = R_i \cap R_{\text{uncov}} \cap R_{\text{struct}}$
    \item $\text{newCov}_{\text{mut}}(t_i) = R_i \cap R_{\text{uncov}} \cap R_{\text{mut}}$
    \item $\text{Score}(t_i) = \alpha \cdot |\text{newCov}_{\text{struct}}(t_i)| + \beta \cdot |\text{newCov}_{\text{mut}}(t_i)|$
  \end{itemize}
  \item Choose a test with maximal score:
  \[
    t_{i^*} = \arg\max_{t_i \in T \setminus S} \text{Score}(t_i)
  \]
  If several tests tie, break ties by the total number of newly covered requirements
  $|\text{newCov}_{\text{struct}}(t_i)| + |\text{newCov}_{\text{mut}}(t_i)|$.
  \item Add $t_{i^*}$ to $S$.
  \item Remove requirements covered by $t_{i^*}$:
  \[
    R_{\text{uncov}} \leftarrow R_{\text{uncov}} \setminus R_{i^*}
  \]
\end{itemize}
5. Return $S$.
\end{framed}

\subsection*{Complexity}

Let $n = |T|$ be the number of tests and $q = |R|$ the number of requirements (structural + mutants). A straightforward implementation:

\begin{itemize}
  \item Computes requirement cardinalities and essential tests in $O(nq)$ time (Phase~1).
  \item In each greedy iteration (Phase~2), scans remaining tests and their coverage sets. If coverage sets are stored as bitsets of length $q$, each score computation is $O(q)$ and each iteration is $O(nq)$.
  \item In the worst case, up to $n$ tests are selected, yielding a worst-case time complexity of $O(n^2 q)$ for Phase~2.
\end{itemize}

Overall, MA-EHGS runs in polynomial time in $n$ and $q$, comparable in practice to other matrix-based greedy heuristics. Efficient bitset implementations and early termination when $R_{\text{uncov}}$ becomes small keep runtimes low for the SRM sizes considered in this thesis.

\chapter{SRM Coverage Extraction Specification}
\label{app:srm}

This appendix specifies how LASSO’s Stimulus--Response Matrices (SRMs) are converted into a requirements matrix suitable for MA-EHGS.

\section*{SRM Structure}

LASSO stores SRMs in an Apache Ignite distributed cache:

\begin{itemize}
  \item \textbf{Rows (stimuli):} test sequences, method invocations, or API calls.
  \item \textbf{Columns (systems):} executable systems under test.
  \item \textbf{Cells:} structured response objects $M_{ij}$ with execution results for system $j$ responding to stimulus $i$.
  \item \textbf{Cache keys (CellId):} include \texttt{executionId}, \texttt{systemId}, \texttt{adapterId}, \texttt{variantId} (original/mutant), \texttt{sheetId} (test or coverage key), and coordinates.
  \item \textbf{Cache values (CellValue):} include execution outputs, coverage elements, or metrics.
\end{itemize}

\section*{Per-Test Coverage Collection}

Per-test coverage is collected via test lifecycle hooks:

\begin{enumerate}
  \item \textbf{Before each test $t_i$:} coverage counters are reset.
  \item \textbf{During $t_i$:} JaCoCo instruments bytecode and records line, branch, and method coverage.
  \item \textbf{After $t_i$:} coverage data are exported for that test only.
\end{enumerate}

Coverage is stored as cells with a uniform naming scheme, e.g.\ \texttt{sheetId = "COVERAGE\_testName"} and a type field indicating whether the value is a line, branch, or method identifier. This design is language-agnostic and can be mirrored for non-Java systems using other coverage tools.

\section*{Mutation Result Collection}

For mutation testing:

\begin{itemize}
  \item Each test $t_i$ is executed against the original system and each mutant variant.
  \item Results are stored with \texttt{sheetId = "testName()"}, and \texttt{variantId} distinguishing original vs.\ individual mutants.
  \item A mutant is considered \emph{killed} by $t_i$ if any SRM cell for $t_i$ and that mutant differs from the original system’s output in the corresponding cell.
\end{itemize}

\section*{Requirements Matrix Construction}

The SRM data are then transformed into a unified requirements matrix:

\begin{itemize}
  \item Tests $T = \{t_1,\dots,t_n\}$ are derived from distinct test names.
  \item Structural requirements $R_{\text{struct}}$ are derived from covered lines, branches, and methods across all tests and systems.
  \item Mutation requirements $R_{\text{mut}}$ are derived from the set of mutant identifiers killed by at least one test and selected for preservation.
  \item For each test $t_i$ and requirement $r_j$, $M_{ij}=1$ if $t_i$ covers $r_j$ (structural) or kills $r_j$ (mutant). Otherwise $M_{ij}=0$.
\end{itemize}

The resulting matrix $M$ is the input to MA-EHGS and to other SRM-based minimisation algorithms.
