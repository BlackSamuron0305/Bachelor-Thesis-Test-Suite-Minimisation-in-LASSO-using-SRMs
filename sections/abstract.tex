\chapter{Abstract}

Software testing has become increasingly resource-intensive, often
consuming a significant fraction of a software project's development
budget\cite{boehm1981}.  Large-scale test suites may include thousands of
automatically generated test cases and take days or even weeks to execute on
modern projects\cite{rothermel1998}.  This escalating complexity and cost
motivate strategies that keep the suite manageable without sacrificing
effectiveness.  Test-suite minimisation aims to eliminate redundant
tests to reduce execution time and maintenance overhead while preserving
coverage and fault-detection capability.  However, naïve reduction can
omit tests that detect faults, thereby undermining software quality\cite{yoo2012}.

This thesis addresses test-suite minimisation for the LASSO
platform using \emph{Stimulus--Response Matrices} (SRMs) that encode test
coverage and mutant-kill information.  We survey existing minimisation
techniques—including greedy heuristics, exact optimisation and
search-based methods—and evaluate them against criteria such as
coverage preservation, reduction ratio, fault-detection retention,
computational cost and suitability for SRM data.  We also discuss why
implementing a bespoke minimiser is preferable to relying on
pre-existing tools that support only specific languages (for example,
JSR): a custom implementation can operate on SRMs generated from any
programming language supported by LASSO.

Based on the analysis, we select the Harrold–Gupta–Soffa (HGS)
algorithm with an overlap-aware extension as the most promising
approach.  The chosen method prioritises tests that uniquely cover rare
requirements and accounts for overlap among test cases to avoid redundant
selections.  The forthcoming implementation will integrate this minimiser
into LASSO, enabling the reduction of large test suites while maintaining
high code coverage and mutation scores.
