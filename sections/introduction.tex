\chapter{Introduction}

\section{Background and Motivation}
Quality assurance through software testing is increasingly challenging as software systems grow in scale and complexity. Testing activities can require substantial time and resources—often accounting for 40--50\% of total development costs~\cite{Boehm1981}. As projects evolve, their test suites tend to expand cumulatively~\cite{Rothermel1998}. Prior studies have observed that regression test suites for enterprise systems may run for days or weeks~\cite{Rothermel1998}, delaying feedback in continuous integration and increasing the cost of each testing cycle. 

Automated test generation techniques exacerbate this issue by producing many overlapping or redundant tests. This leads to bloated test suites that are harder to maintain while adding little new coverage~\cite{Yoo2012}. Industry standards such as ISO/IEC/IEEE 29119~\cite{ISO29119} emphasize systematic test design and maintenance, highlighting the need for techniques like \textit{test suite minimization}~\cite{Wong1995}. Minimization aims to remove redundant tests while preserving coverage and fault-detection effectiveness. Since finding the optimal minimal subset is NP-complete~\cite{Wong1995}, practical approaches rely on heuristics such as greedy set-cover approximations, clustering, or machine learning~\cite{Yoo2012,Noemmer2020}. 

Empirical studies show the trade-offs involved: Noemmer and Haas~\cite{Noemmer2020} found that minimization can reduce suite size by 70\% while incurring an average 12.5\% loss in fault detection. This balance between efficiency and effectiveness underscores the importance of careful selection of minimization techniques.

\section{LASSO Context}
The \textbf{LASSO} platform (Large-Scale Software Observatorium) was developed at the University of Mannheim to support scalable software analysis and experimentation~\cite{Kessel2022}. It integrates static and dynamic analysis at scale, supports automated test generation, and provides a domain-specific language (LSL) for orchestrating analysis pipelines. Despite these capabilities, LASSO currently lacks automated test suite minimization. As a result, generated test suites may grow excessively large, undermining LASSO's efficiency. Integrating minimization techniques directly into LASSO will reduce redundant test execution and improve throughput in large-scale testing workflows.

\section{Problem Statement}
While LASSO provides robust test generation and analysis, it lacks functionality for reducing redundant test suites. This leads to:
\begin{itemize}
    \item Increased execution times,
    \item Higher computational and storage costs,
    \item Maintenance overhead, and
    \item Reduced efficiency of continuous integration workflows.
\end{itemize}
This thesis investigates how test suite minimization can be integrated into LASSO to address these issues.

\section{Research Objectives}
The objectives of this thesis are:
\begin{enumerate}
    \item To survey state-of-the-art test suite minimization techniques and tools for Java.
    \item To benchmark these techniques on real-world Java projects, measuring reduction ratio, coverage, and fault-detection preservation.
    \item To select the best-performing approach based on empirical results.
    \item To integrate this approach into the LASSO platform's pipeline.
    \item To evaluate the integration's impact on LASSO's efficiency and effectiveness.
\end{enumerate}

\section{Research Questions}
\begin{enumerate}
    \item What test suite minimization techniques and tools are available for Java, and what are their strengths and limitations?
    \item How do these techniques perform in terms of reduction ratio, coverage preservation, and fault-detection effectiveness?
    \item Which approach provides the best trade-off between efficiency and effectiveness for integration into LASSO?
    \item What are the benefits and drawbacks of integrating minimization into LASSO's workflow?
\end{enumerate}
