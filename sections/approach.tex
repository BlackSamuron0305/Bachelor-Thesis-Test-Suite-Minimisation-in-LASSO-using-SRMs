\section{Algorithm Selection Rationale}

The multi-criteria evaluation framework established in Chapter~\ref{chap:evaluation} reveals that test suite minimization algorithms must balance competing objectives: reduction effectiveness, coverage preservation, fault detection retention, computational efficiency, and practical implementability. Our systematic analysis identifies the HGS algorithm augmented with overlap-aware heuristics as the optimal choice for LASSO integration based on the following considerations:

\subsection{Superior Coverage Preservation}
HGS demonstrates exceptional performance in preserving both structural coverage and mutation scores by prioritizing tests that cover rare requirements. This characteristic addresses a fundamental limitation of classical greedy approaches, which may inadvertently select redundant tests while overlooking those with unique coverage profiles. Harrold et al.~\cite{harrold1993} demonstrated that HGS maintains higher coverage ratios compared to baseline approaches while achieving substantial reduction ratios between 45\% and 70\%. Subsequent studies have corroborated these findings across different testing contexts~\cite{noemmer2020}.

\subsection{Enhanced Fault Detection Through Overlap Awareness}
The integration of overlap-aware heuristics addresses HGS's potential limitation of selecting tests with substantial coverage duplication. Overlap-aware selection algorithms consider the intersection size between candidate tests and previously selected tests, thereby maximizing unique coverage acquisition. Bach et al. demonstrated that overlap-aware approaches achieve up to 50\% higher code coverage within fixed time budgets compared to traditional greedy methods~\cite{bach2017}, suggesting superior fault detection retention.

\subsection{Computational Efficiency and Scalability}
HGS maintains polynomial time complexity $O(nm \log m)$ where $n$ represents test cases and $m$ represents requirements, making it suitable for large-scale SRM processing. The addition of overlap computation introduces manageable overhead while preserving scalability characteristics essential for industrial applications within LASSO.

\subsection{SRM Compatibility and Language Independence}
Unlike approaches requiring program structural information (e.g., REDUNET's CFG analysis~\cite{mongiovi2020}), our selected approach operates exclusively on the SRM representation. While LASSO's SRMs canonically capture system responses to stimuli for multi-system behavioral analysis, our minimization approach leverages LASSO's adapted SRM view where stimuli represent test cases and systems represent coverage requirements within a single target system. This enables our algorithm to operate on the resulting coverage matrix while maintaining compatibility with LASSO's language-independent analysis paradigm and unified SRM infrastructure. This characteristic enables consistent minimization across diverse programming languages without requiring language-specific adaptations.

\subsection{Algorithm Specification}

\textbf{Algorithm 1: Enhanced HGS with Overlap-Aware Selection}
\begin{enumerate}
  \item \textbf{Initialization Phase:}
  \begin{itemize}
    \item Input: Coverage-adapted SRM $M \in \{0,1\}^{n \times m}$ where $n$ stimuli (test cases) and $m$ systems (coverage requirements), optional test execution weights $W = \{w_1, w_2, \ldots, w_n\}$
    \item Initialize reduced suite $S = \emptyset$, covered requirements $R_{covered} = \emptyset$
    \item Compute requirement cardinalities: $card_j = \sum_{i=1}^{n} M_{ij}$ for all $j \in \{1, \ldots, m\}$ (number of tests covering each requirement)
  \end{itemize}
  
  \item \textbf{Unique Coverage Selection:}
  \begin{itemize}
    \item $\forall j$ where $card_j = 1$: Select test $t_i$ such that $M_{ij} = 1$
    \item Add selected tests to $S$, mark corresponding requirements as covered
    \item Update cardinalities for remaining requirements
  \end{itemize}
  
  \item \textbf{Overlap-Aware Greedy Selection:}
  \begin{itemize}
    \item While uncovered requirements remain:
    \item For each uncovered test $t_i$, compute effectiveness ratio:
    \begin{equation}
    effectiveness_i = \frac{|new\_coverage_i|}{w_i \times (1 + overlap\_penalty_i)}
    \end{equation}
    where:
    \begin{itemize}
      \item $new\_coverage_i = \{j : M_{ij} = 1 \text{ and } j \notin R_{covered}\}$
      \item $w_i$ represents the execution weight of test $t_i$ (default: 1.0)
      \item $overlap\_penalty_i = \alpha \times \frac{\sum_{t_k \in S} |C(t_i) \cap C(t_k)|}{|C(t_i)|}$ with $\alpha = 0.5$
    \end{itemize}
    \item Select test with maximum effectiveness ratio: $t^* = \arg\max_{t_i} effectiveness_i$
    \item Update: $S = S \cup \{t^*\}$, $R_{covered} = R_{covered} \cup C(t^*)$
    \item Recalculate requirement cardinalities for remaining tests
  \end{itemize}
  
  \item \textbf{Post-Processing Optimization:}
  \begin{itemize}
    \item Perform redundancy elimination: remove tests from $S$ whose requirements are covered by remaining tests
    \item Optional: Verify mutation score preservation and adjust selection if necessary
  \end{itemize}
  
  \item \textbf{Output Generation:}
  \begin{itemize}
    \item Generate minimized SRM $M' \subseteq M$ containing only selected test cases (stimuli)
    \item Produce analysis report including reduction metrics and coverage preservation statistics
  \end{itemize}
\end{enumerate}

\subsection{Integration Architecture}

The minimization framework integrates into LASSO's analysis pipeline through the following components, operating on LASSO's coverage-adapted SRM representation:

\begin{itemize}
  \item \textbf{SRM Preprocessor:} Validates input SRM format from LASSO's test generation pipeline, handles missing data, and computes auxiliary data structures while maintaining compatibility with LASSO's unified SRM infrastructure
  \item \textbf{Minimization Engine:} Implements the core algorithm with configurable parameters for overlap sensitivity and effectiveness weighting, operating on the adapted SRM where rows represent test stimuli and columns represent coverage requirements
  \item \textbf{Quality Assessor:} Evaluates reduction quality using metrics including coverage retention, mutation score preservation, and fault detection estimation
  \item \textbf{Results Exporter:} Generates optimized SRMs in LASSO-compatible formats and produces comprehensive analysis reports that can be further processed through LASSO's SRMPATH notation and external analytics tools
\end{itemize}

\section{Evaluation Methodology}

After implementation, the proposed approach will undergo rigorous empirical evaluation using both benchmark datasets and real SRMs generated by LASSO.

\subsection{Evaluation Datasets}
\begin{itemize}
  \item \textbf{Benchmark Projects:} 10-15 open-source Java projects from the Defects4J dataset
  \item \textbf{LASSO-Generated SRMs:} Real coverage matrices from projects analyzed within LASSO
  \item \textbf{Synthetic Data:} Controlled SRMs with varying sparsity and overlap characteristics
\end{itemize}

\subsection{Performance Metrics}
\begin{itemize}
  \item \textbf{Reduction Ratio:} $RR = \frac{|T| - |S^*|}{|T|} \times 100\%$
  \item \textbf{Coverage Retention:} $CR = \frac{|C(S^*)|}{|C(T)|} \times 100\%$
  \item \textbf{Mutation Score Preservation:} $MSP = \frac{MS(S^*)}{MS(T)} \times 100\%$
  \item \textbf{Fault Detection Loss:} Percentage of seeded faults missed by reduced suite
  \item \textbf{Algorithm Runtime:} Wall-clock time for minimization process
\end{itemize}

\subsection{Success Criteria}
\begin{itemize}
  \item Achieve $\geq 45\%$ reduction ratio while maintaining $\geq 95\%$ coverage retention
  \item Preserve $\geq 90\%$ of mutation score
  \item Runtime complexity remains $O(nm \log m)$ for matrices with $n \leq 10,000$ tests
  \item Outperform classical greedy by $\geq 10\%$ in fault detection retention
\end{itemize}

\subsection{Statistical Analysis}
Results will be analyzed using repeated measures ANOVA with significance level $\alpha = 0.05$. Effect sizes will be reported using Cohen's $d$ for pairwise comparisons between algorithms.
