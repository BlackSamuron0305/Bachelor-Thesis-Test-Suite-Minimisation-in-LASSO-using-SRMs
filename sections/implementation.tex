\chapter{Implementation}
\label{chap:implementation}

This chapter presents the implementation of the Harrold--Gupta--Soffa (HGS) algorithm with overlap awareness for test suite minimization in LASSO. We describe the software architecture, algorithm implementation, and platform integration, followed by empirical validation of correctness and performance characteristics.

\section{Software Architecture}

The implementation consists of four components integrated into LASSO's testing infrastructure: \texttt{OverlapAwareHGSMinimizer} (core 4-phase algorithm), \texttt{TestCase} (data model with BitSet coverage encoding), \texttt{MinimalTestSuite} (result container), and \texttt{HGSMinimizerDemo} (demonstration with 5 usage scenarios). All components follow LASSO conventions and GPL3 licensing.

\section{Algorithm Implementation}

\subsection{Mutation-Aware HGS Algorithm}

Building on the Harrold--Gupta--Soffa (HGS) greedy heuristic, mutation coverage is directly integrated into the effectiveness calculation. Jehan and Wotawa~\cite{jehan2023} demonstrated that greedy minimisation using mutation coverage as a requirement metric achieves $\approx$70\% reduction with negligible loss in fault-detection capability. The algorithm therefore extends HGS with a scalar weight $\beta$ that rewards tests killing new mutants while retaining the overlap penalty $\alpha$ from structural optimisation:
\begin{equation}
\text{effectiveness}(t_i) = \frac{|\text{newStruct}_i| + \beta \cdot |\text{newMutants}_i|}{w_i \cdot (1 + \alpha \cdot \text{overlap}_i)}.
\end{equation}

Default parameters are $\alpha = 0.5$ and $\beta = 0.75$, which yielded Pareto-robust results across all evaluated projects (cf.\ Jehan \& Wotawa~\cite{jehan2023}).

Let $T = \{t_1, t_2, \ldots, t_n\}$ denote the set of tests (stimuli), $R = \{r_1, r_2, \ldots, r_m\}$ the set of structural requirements (coverage elements), and $\mathcal{M} = \{m_1, m_2, \ldots, m_p\}$ the set of mutants. For each test $t_i$, let $C(t_i) \subseteq R$ denote the set of requirements covered by $t_i$ and $K(t_i) \subseteq \mathcal{M}$ denote the set of mutants killed by $t_i$. The algorithm produces a reduced test suite $S \subseteq T$ that preserves coverage $C(S) = C(T)$ while maximizing mutation kill capability.

\textbf{Phase 1: Initialization.} Compute requirement cardinalities $\text{card}(r_j) = |\{t_i \in T \mid r_j \in C(t_i)\}|$ for all $r_j \in R$. Initialize $S = \emptyset$ and $R_{\text{covered}} = \emptyset$.

\textbf{Phase 2: Unique Structural Coverage Selection.} For each requirement $r_j \in R$ with $\text{card}(r_j) = 1$, add the unique covering test to $S$ and update $R_{\text{covered}}$ accordingly.

\textbf{Phase 3: Mutation-Aware Overlap-Penalized Greedy Selection.} While $R_{\text{covered}} \neq R$, select tests iteratively using the mutation-aware effectiveness function:
\begin{equation}
\text{effectiveness}(t_i) = \frac{|\text{newStruct}(t_i)| + \beta \cdot |\text{newMutants}(t_i)|}{w_i \cdot (1 + \alpha \cdot \text{overlap}(t_i))},
\end{equation}
where
\begin{align}
\text{newStruct}(t_i) &= C(t_i) \setminus R_{\text{covered}}, \\
\text{newMutants}(t_i) &= K(t_i) \setminus \mathcal{M}_{\text{covered}}, \\
\text{overlap}(t_i) &= \frac{|C(t_i) \cap R_{\text{covered}}|}{|C(t_i)|},
\end{align}
with $\mathcal{M}_{\text{covered}} = \bigcup_{t_j \in S} K(t_j)$ denoting the set of mutants killed by currently selected tests. Select $t^* = \arg\max_{t_i \notin S} \text{effectiveness}(t_i)$, add $t^*$ to $S$, and update $R_{\text{covered}}$ and $\mathcal{M}_{\text{covered}}$.

\textbf{Phase 4: Redundancy Elimination.} Remove tests $t_i \in S$ whose coverage and mutation kills are subsumed by other selected tests.

The overlap-penalty $\alpha$ penalises redundant structural coverage, while the mutation-weight $\beta$ rewards tests that uniquely kill additional mutants. Based on sensitivity analyses by Bach et al.~\cite{bach2017} and Jehan \& Wotawa~\cite{jehan2023}, $\alpha = 0.5$ and $\beta = 0.75$ provide a balanced trade-off between suite reduction and semantic retention. Both parameters remain tunable per project. Complete implementation pseudocode is provided in Appendix~\ref{app:pseudocode}.

\section{Implementation Design Decisions}

To ensure alignment with empirically validated techniques, only the integrated $\beta$-weighted approach was retained. While earlier drafts included a pre-phase locking unique mutant killers, subsequent evaluation showed that direct mutation-coverage integration achieves comparable mutation retention with lower complexity, consistent with Jehan \& Wotawa~\cite{jehan2023}. The final implementation therefore relies solely on the heuristic integration model.

\subsection{Algorithm Parameters ($\alpha$, $\beta$)}

The effectiveness metric is governed by two scalar parameters and auxiliary configuration flags:
\begin{itemize}
  \item $\alpha \in [0,1]$ (overlap penalty): increases the denominator to penalize tests whose coverage overlaps strongly with already selected tests; higher values promote diversity.
  \item $\beta \in [0,2]$ (mutation weighting): scales the contribution of newly killed mutants relative to newly covered structural requirements in the numerator; higher values emphasize mutation retention.
  \item \texttt{useMutationScore} (bool): when enabled, includes mutation-kill information in the BitSet representation used by the selector.
  \item \texttt{reportStats} (bool): emits reduction ratio, coverage retention, and mutation retention summaries for auditability.
  \item \texttt{updateAbstraction} (bool): persists the reduced SRM abstraction back into the repository for downstream analyses.
\end{itemize}

  extbf{Recommended configurations.} For general-purpose SRM minimization, we recommend $\alpha = 0.5$, $\beta = 0.75$, \texttt{useMutationScore}=\texttt{true}, \texttt{reportStats}=\texttt{true}, and \texttt{updateAbstraction}=\texttt{true}. These defaults balance reduction effectiveness with coverage and mutation retention in line with empirical evidence~\cite{bach2017,jehan2023}.

\subsection{Parameter Tuning and Sensitivity Analysis}

The algorithm includes two scalar coefficients ($\alpha$, $\beta$). Their optimal values are determined empirically through a coarse-to-fine grid search across representative projects (e.g., Defects4J~\cite{just2014}) using $\alpha \in \{0.3, 0.5, 0.7\}$ and $\beta \in \{0.5, 0.75, 1.0\}$. For each pair, the reduction ratio (RR), structural coverage retention (CR), and mutation retention (MR) are measured. Feasible configurations satisfy CR $\geq$ 95\% and MR $\geq$ 90\%. Among feasible pairs, the configuration maximizing RR is selected. In all evaluated projects, ($\alpha = 0.5$, $\beta = 0.75$) was Pareto-robust, confirming its use as default in LASSO.

\section{Test Weights}

The implementation supports weighted minimization by incorporating execution costs into the effectiveness metric, penalizing slower tests while maintaining $O(n \cdot m \cdot \log m)$ complexity.

\section{Empirical Validation}
\label{sec:impl-validation}

We implement a verification suite that exercises core correctness properties of the minimizer: preservation of target coverage, handling of unique-coverage requirements, effect of overlap penalisation, and weight sensitivity. These tests ensure conformance with the algorithmic specification in this chapter and the pseudocode in Appendix~\ref{app:pseudocode}.

\subsection{Validation Methodology}

We validate the implementation via small-scale unit tests on synthetic SRMs and micro-benchmarks:
\begin{itemize}
  \item \textbf{Unit tests:} correctness of Phase~1 unique-coverage selection; stability of overlap penalty w.r.t. $\alpha$; coverage equality $C(S^*)=C(T)$.
  \item \textbf{Benchmarks:} runtime trends on sparse vs. dense SRMs (varying $n, m$); reduction ratio vs. coverage retention under different overlap penalties.
\end{itemize}

\subsection{Test Datasets}
\begin{itemize}
  \item \textbf{Benchmark Projects:} 10--15 Defects4J projects~\cite{just2014}.
  \item \textbf{LASSO SRMs:} Real coverage matrices from LASSO~\cite{Kessel2022}.
  \item \textbf{Synthetic:} Controlled sparsity/overlap for stress tests.
\end{itemize}

\subsection{Evaluation Metrics}
\begin{itemize}
  \item \textbf{Reduction Ratio:} $RR = \tfrac{|T| - |S^*|}{|T|} \times 100\%$.
  \item \textbf{Coverage Retention:} $CR = \tfrac{|C(S^*)|}{|C(T)|} \times 100\%$ (incl. mutation score).
  \item \textbf{Fault Detection Loss:} Missed faults relative to original~\cite{shi2018}.
  \item \textbf{Runtime:} Minimization wall-clock time.
\end{itemize}

\subsection{Success Criteria}
\begin{itemize}
  \item $RR \geq 45\%$, $CR \geq 95\%$, mutation preservation $\geq 90\%$~\cite{harrold1993,yoo2012}.
  \item Runtime remains $O(nm\log m)$ up to $n \leq 10{,}000$.
  \item $\geq 10\%$ fault detection retention improvement over classical greedy.
\end{itemize}

\subsection{Statistical Analysis}
Repeated measures ANOVA at $\alpha=0.05$ across identical datasets, effect sizes via Cohen's $d$ with bootstrap CIs.

\subsection{Results}

On synthetic SRMs, overlap-aware HGS shows improved unique coverage acquisition compared to classical greedy at comparable runtime, particularly for moderate overlap regimes, consistent with literature~\cite{harrold1993,bach2017}. Parameter sensitivity remains bounded under $\alpha \in [0.3,0.7]$.

Extended benchmarking artefacts, overlap statistics, and reproducibility notes are provided in Appendix~\ref{app:benchmarks}. Quantitative comparison across algorithms is reported in Chapter~\ref{chap:comparison} to avoid duplication.

\section{Integration with LASSO Platform}
\label{sec:lasso-integration}

The minimizer integrates with LASSO's SRM-based execution pipeline as follows:

\begin{enumerate}
  \item \textbf{SRM Input:} Read existing SRMs from LASSO's backend storage, where each SRM contains structured response objects generated by Actuation Sheets and Sequence Sheets during experimental execution.
  
  \item \textbf{System Selection:} Select a target system (column) for minimization. The current implementation focuses on single-system minimization; multi-system extension is identified as future work (Section~\ref{sec:future-work}).
  
  \item \textbf{Coverage Extraction:} Parse response objects from the selected system column to extract coverage metrics (statement/branch coverage, mutation scores) embedded in each $M_{ij}$ cell.
  
  \item \textbf{Minimization:} Apply the HGS algorithm with overlap-aware heuristics using the extracted coverage data to select a minimal subset of stimuli.
  
  \item \textbf{SRM Output:} Generate a reduced SRM containing only selected stimuli (rows) while preserving the original schema (systems as columns, structured response objects in cells). Store or replace this reduced SRM in LASSO for subsequent analyses.
\end{enumerate}

Integration via LASSO's LSL (LASSO Specification Language) supports declarative minimization policies through a \texttt{TestSuiteMinimization} action with configurable algorithm selection, overlap penalty, coverage criteria, and weighting. A formal specification of coverage extraction from SRM response objects is provided in Appendix~\ref{app:srm}.

\subsection{Execution Flow and Data Extraction}
\label{sec:exec-flow}

The end-to-end execution comprises three stages integrated in the LASSO pipeline~\cite{Kessel2022}:
\begin{enumerate}
  \item \textbf{Acquisition.} The LSL action resolves the target execution (\texttt{executionId}) and abstraction (\texttt{abstractionId}), then queries the SRM-backed storage for structural coverage records. We restrict to instruction and branch coverage for consistency across systems:
\begin{lstlisting}[language=SQL]
SELECT sheetId, systemId, type, value
FROM CELLVALUE
WHERE executionId = ?
  AND abstractionId = ?
  AND (type LIKE '%INSTRUCTION_COVERED%'
       OR type LIKE '%BRANCH_COVERED%');
\end{lstlisting}
  Each row is parsed into a compact bit-level representation keyed by test (row) and requirement (column).

  \item \textbf{Assembly.} For each test $t_i$, we build two disjoint BitSets: (i) $B^{cov}_i$ for structural coverage (instruction/branch), and (ii) $B^{mut}_i$ for mutants killed by $t_i$. Mutation kills are inferred by comparing the observed outputs of the original and mutated program versions; a mutant is considered killed if the observable behavior diverges beyond the configured oracle~\cite{yoo2012,just2014}. We concatenate these into a single vector $B_i = [B^{cov}_i \mid B^{mut}_i]$ for set-operations, while the effectiveness function applies the scalar weight $\beta$ to the mutation segment during scoring (no physical duplication of bits is required).

  \item \textbf{Selection.} The minimizer invokes the overlap-aware HGS selector with the assembled BitSets and parameters $(\alpha,\beta)$, returning the reduced suite $S^*$ and summary statistics. The call signature in the prototype is:
\begin{lstlisting}[language=Java]
MinimalTestSuite Sstar =
  OverlapAwareHGSMinimizer.select(
      tests /* T */, requirements /* Req */, alpha, beta,
      /* flags: */ useMutationScore, reportStats, updateAbstraction);
\end{lstlisting}
  The result is serialized back into a reduced SRM with the original schema to preserve downstream compatibility in LASSO~\cite{Kessel2022}.
\end{enumerate}
